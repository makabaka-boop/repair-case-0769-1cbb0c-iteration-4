# 植物标本标签预检台

面向小型标本馆与野外团队的纯前端预检工具。记录和问题处理状态保存在浏览器 `localStorage`，无需后端。

## 本地运行

```bash
npm install
npm run dev
npm test
npm run build
```

## 数据交换

CSV 必须使用以下顺序和名称的 UTF-8 表头：

```text
采集编号,物种名称,采集人,采集日期,地点,纬度,经度,生境备注
```

采集编号、采集人、采集日期、地点为必填项。日期采用 `YYYY-MM-DD`；纬度范围为 -90～90，经度范围为 -180～180。导入会一次性校验全部行；任一行失败时不会写入任何数据。JSON 导出包含完整记录和问题处理说明；非法 JSON 导入同样不会改变当前数据。

合作单位的 CSV 若列名或列序不同，无需先改表头：选择文件后会打开字段映射面板，把来源列对应到采集编号、物种名称等字段即可（与标准字段同名的列会自动预填）。采集编号、采集人、采集日期、地点必须各有来源，且每个来源列只能使用一次；未映射的字段按空值导入。来源列值按原样保留（含首尾空格），预览所见即导入所得。确认后仍按同一套日期、坐标、重复编号规则校验，任一行不合法则整批不写入；取消、校验失败或本地写入失败（如存储空间不足）都不会改变当前记录、撤销项和打印批次。

## 容器运行

```bash
docker compose up -d --build
curl http://localhost:8082/health
docker compose down
```

覆盖宿主端口：`WEB_PORT=9090 docker compose up -d --build`。

## 说明

- “已修正”和“确认保留”是人工处置状态；编辑记录后问题会实时重新计算。
- 保存对已有记录的编辑后，工具栏下方会出现一次性的“撤销本次编辑”入口（标明采集编号）。点击可将整条记录恢复到保存前内容并重新计算问题清单；新增记录和问题处置不在撤销范围内。撤销项以编辑前快照独立保存在浏览器中，刷新页面仍可撤销，但只保留最近一次编辑。删除该记录、导入 JSON、载入示例或清空数据会清除撤销项；快照损坏或目标记录丢失时会提示“最近编辑已无法撤销”。
- “采集编号重复”问题提供“合并比较”入口。比较范围固定为当前两条同号记录：选择保留项后逐字段选取内容，确认会生成一条合并记录、重新计算预检问题，并立即写入现有本地工作集。保留项继续使用原内部编号；被合并项若在打印批次中，会改指保留项并按最早加入位置去重。合并后会对生成的记录重新计算预检问题：问题对应字段若改取了另一条记录的内容，原有人工处置不再沿用，新出现的问题重新显示为“待处理”；仅当字段仍取自保留项且问题依旧存在时，才延续“已修正/确认保留”状态。确认前记录被删除、编号已变化或写入失败时会拒绝提交，原工作集、问题处置与批次保持不变。
- “近地点复核”工作区用于找出编号不同、却可能在同一采集点重复登记的两份标签：仅纳入采集编号、采集人、采集日期、物种齐备且坐标合法的记录，按相同采集人、日期与物种分组，再用 haversine 球面距离（平均地球半径 6371000 米）找出不超过所填 1～1000 米半径的记录对。跨 180° 经线按最短经度差计算；是否在半径内一律用未舍入距离判定（边界含等于），卡片上的距离才保留一位小数。每对只出现一次、按双方内部记录 ID 稳定排序，逐对直接判定，不会由 A—B、B—C 自动推断出 A—C；采集编号相同的记录仍归“采集编号重复”问题，不进入复核。标本员可逐对标记“同点复采”或“确为两份”，结论绑定双方编号、物种、采集人、日期、纬度、经度六个字段的指纹，独立保存在浏览器（`plant-preflight-near-v1`）；随后任一方成功修改这些字段，或记录被删除，仅该对结论立即失效、从浏览器存储中剔除并回到待复核（改地点、生境备注不影响结论）：此后把字段改回原文、撤销本次编辑或恢复含相同内部编号的备份都不会使其复活，只有重新逐对确认才能恢复。浏览器写入失败时不更新界面、不留下已确认的假象。复核操作不改写原始记录、现有“采集编号重复”等问题处置、撤销项与打印批次。
- “关系检查”是只读的采集点关系汇总：仅取当前仍有效的结论，把“同点复采”连成采集点分组；若某条“确为两份”的两端落在同一分组，则列为冲突卡片，给出连接两端的最短同点路径与相异关系（路径并列时按内部记录 ID 序列取唯一结果）。未复核的近地点对不会被自动写成已确认。分组、冲突卡片与打印批次预览中的警示使用同一份计算结果，点击警示可定位批次中卷入冲突的标签；检查不改写结论、记录与打印批次，编辑、删除、撤销及备份恢复后按现有结论失效规则即时重算，旧版存储没有结论时显示空报告。
- 预览中的二维码以可编码文本展示，不依赖扫码库。
- 需要一次打印多份标签时，在记录卡片上点击“加入批次”，批次按加入顺序保存在浏览器中（重复加入不增量，“移出批次”可移除）。工具栏的“打印批次”打开分页预览，每份标本确定性排入 A4 每页 8 格（2 列 × 4 行），超过 8 份自动跨页，确认后一次调用浏览器打印。仍有未处置问题的标本会在预览中标注但不阻止打印。导入 JSON、载入示例或删除记录后若批次成员失效，打开预览时会自动剔除并提示；批次为空时只反馈“请先选择标本”，不改变当前工作集。
- 当前数据只存在于当前浏览器环境，建议定期导出 JSON 备份。
